Status: all four follow-ups from the spike are in the production ball stage. The new trajectory is switchable with ball.trajectory: hybrid and ships opt-in. It clearly improves gberch and s013 and every synthetic test, but real-footage error gets worse on the two flight-heavy clips (origi01, kroupi01), so the default stays reference. On this page, "current" means the default reference trajectory.

The four follow-ups

  • Trajectory layer in the stage. Ported to src/utils/ball_hybrid_* and wired behind ball.trajectory. Auto events pass a stricter gate (kind, confidence, agreement with nearby detections, span-residual and launch-speed checks). Two integration bugs found by per-anchor analysis are fixed: the gate had been reading the wrong confidence field, so no auto event was ever accepted, and implausibly fast flights between close-together touches now fall back to a roll.
  • Replay angles as fixed points. Replay-triangulated positions become depth-hard knots after a check that operator clicks win and a physical-volume check. On origi01 the error at held-out replay positions is 0.62 m (target ≤ 0.8 m). When every position from a replay angle is rejected, the stage now proposes reviewing that angle's camera in the anchor editor, which is the fix s013's six replays need.
  • Single-camera event cues. Audio, goal-net motion and motion blur are all built and measured with train/test clip splits. Blur is the only cue whose tuned thresholds held up on unseen clips. A weighted fusion that looked best on the tuning clips was the worst on held-out clips. No fusion rule beat the auto events on held-out F1, so cues ship off (ball.hybrid.cues.enabled: false); only audio is wired into the stage so far.
  • Spin. A bounded two-axis spin fit (topspin/backspin and sidespin, up to 10 rev/s) that keeps both endpoints exact. It recovers known spin to within 20% and 15°, with no false detections in 50 spin-free trials, and never makes in-air accuracy worse on the four clips (kroupi01 improves from 61% to 68% within 20 cm). It's off by default until real clips are checked; when on, the fitted spin drives the ball's rotation in the export.

Regression gate

The ball stage now has a golden-clip gate like the camera stage: pytest tests/test_ball_regression.py -m regression. It checks synthetic accuracy, ground float/sink, naturalness and real held-out error against committed baselines. Baselines were captured with one run per clip to save time, so run-to-run spread isn't measured yet; the gate uses fixed tolerances (5 points on % within 20 cm, 20% relative on p95 and real median).

What's still open

  • origi01 and kroupi01 real regression. It isn't the auto-event gate: the stage's diagnostics show 54 candidates, 2 accepted and 23 rejected for disagreeing with the detections. The next lead is how the reference solver handles touch-dense spans compared with the hybrid's flight split, which leaves some spans at 200–800 px.
  • Net and blur cues need a shared video-decode pass before they can run inside the stage.
  • Audio noise suppression needs a re-tune on more clips that have usable match audio.
